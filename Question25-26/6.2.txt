

Q6(ii). Explain in detail the various types of data representation used in digital computers. Discuss the characteristics and use cases of each data type.


=>Data Representation in Digital Computers

Introduction:
A digital computer stores and processes all information in binary form (0 and 1). Data representation means the way different kinds of data (numbers, characters, signs, fractions) are encoded into binary patterns so the hardware can store and process them.

Data in a digital computer is classified as:

Data Representation
├── 1. Data Types
│     ├── Number systems (Binary, Octal, Decimal, Hexadecimal)
│     ├── Alphanumeric codes (ASCII, EBCDIC)
│     └── Other binary codes (BCD, Gray code, Parity)
├── 2. Complements (for signed numbers and subtraction)
├── 3. Fixed Point Representation
└── 4. Floating Point Representation



1. Data Types
(a) Number Systems:

System	      Base	Digits	       Use
Binary	       2	0, 1	       Internal processing and storage
Octal	       8	0–7	       Compact form of binary (3 bits = 1 digit)
Decimal	       10	0–9	       Human input and output
Hexadecimal    16	0–9, A–F       Memory addresses, debugging (4 bits = 1 digit)

b) Alphanumeric (Character) Codes:

ASCII: A 7-bit code with 128 symbols (letters, digits, punctuation, control characters). For example, ‘A’ = 65 and ‘a’ = 97. Used in keyboards, text files, and communication.

EBCDIC: An 8-bit code with 256 symbols. Used in IBM mainframes.

(c) Other Binary Codes:

BCD (Binary Coded Decimal): each decimal digit is stored in 4 bits, so 45 = 0100 0101. It makes decimal conversion easy and is used in calculators and digital clocks.
Gray code: Only one bit changes between successive values. Used in rotary encoders and K-maps.
//Parity bit: an extra bit added for single-bit error detection. Used in data transmission and memory.



2. Complements

Complements represent negative numbers and perform subtraction by addition, which simplifies hardware. For a base r system there are two types:

//Type	                        Binary	          // Decimal
//(r−1)’s complement	        1’s complement	  // 9’s complement
//r’s complement	        2’s complement	  // 10’s complement

Rules:

1’s complement: invert every bit. Example: 10110 → 01001.
2’s complement: 1’s complement + 1. Example: 10110 → 01001 + 1 = 01010.
9’s complement: subtract each digit from 9. Example: 546700 → 453299.
10’s complement: 9’s complement + 1. Example: 546700 → 453300.

Subtraction using 2’s complement: To compute A − B, add A to the 2’s complement of B. If a carry is generated, discard it and the result is positive. If there is no carry, the result is negative and is in 2’s complement form.



3. Fixed Point Representation:

In fixed point representation, the binary point is at a fixed position, usually at the extreme right so the number is an integer. The leftmost bit is the sign bit (0 = positive, 1 = negative).

Three methods for signed numbers (example: −9 in 8 bits):
Method	                Representation of −9
Signed-magnitude	1 0001001
Signed 1’s complement	1 1110110
Signed 2’s complement	1 1110111

Characteristics:

Simple and fast arithmetic, with less hardware.
The range is limited. For n bits in 2’s complement the range is −2ⁿ⁻¹ to +(2ⁿ⁻¹ − 1), so 8 bits give −128 to +127.
Overflow can occur if the result exceeds the range.
Signed-magnitude and 1’s complement have two zeros (+0 and −0). 2’s complement has only one zero, so it is the most widely used.

Use cases: integer arithmetic, loop counters, array indexing, embedded systems, and DSP.



4.Floating Point Representation:

floating-point representation is a method of representing real numbers,
including very large and very small numbers, in a computer.

Main Parts:
1. Sign bit (S): 0 means positive, 1 means negative.
2. Exponent (E): Biased exponent, it determines the position of the binary point.
3. Mantissa (Significand): Stores the significant digits of the number.

Formula:
x = (-1)^s * (1.f)2 * 2^(E - bias)

Normalisation:
The number is stored in the form 1.f. The leading 1 is not stored
(hidden bit).

IEEE 754 Standard:

                 Sign    Exponent    Fraction    Bias
Single (32-bit)  1 bit   8 bits      23 bits     127
Double (64-bit)  1 bit   11 bits     52 bits     1023

Example: Represent -13.25 in 32-bit format

Step 1: Sign = 1 (negative number)
Step 2: 13.25 = 1101.01 (binary)
Step 3: Normalise: 1101.01 = 1.10101 * 2^3
Step 4: Exponent: E = 3 + 127 = 130 = 10000010 (binary)
Step 5: Fraction = 10101 followed by zeros, to make 23 bits
        = 10101000000000000000000

Result (32-bit):
Sign | Exponent   | Fraction
1    | 10000010   | 10101000000000000000000

Characteristics:

Represents a very wide range of numbers, from very small to very large.
Normalisation keeps the leading digit of the mantissa non-zero, which gives maximum precision.
Precision is limited, so rounding errors can occur.
Arithmetic is slower and needs more complex hardware than fixed point.
Has special values: ±0, ±∞, and NaN.

Use cases: scientific and engineering calculations, graphics, simulations, and machine learning.
